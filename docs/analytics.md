# Analytics

NeoAgent uses Umami browser analytics by default for its landing page and web app. Set `ANALYTICS_ENABLED=false` in the server's `.env` file (normally `~/.neoagent/.env`) and restart the server to disable it for the whole instance. No browser or server analytics requests are made when disabled. Browsers that send Do Not Track or Global Privacy Control are also respected.

The browser sends a coarse page category (landing or app), language and screen size, a page load duration range, navigation events, counts of clicks and browser errors, a once-per-minute event while a browser tab is visible, and aggregated counts of requests to selected product and admin feature groups, split into read/write and broad success or error categories. Admin groups include the fixed sections available in each app, such as users, settings, updates, and operational status; individual user IDs and settings values are not collected. These measurements help assess usage and reliability; they do not include request paths, bodies or response contents, error messages, page content, prompts, responses, recordings, transcripts, credentials, account identifiers, full URLs, query strings, or referrers in analytics payloads. The analytics service at `data.neo.eu.com` receives the browser's IP address and normal network request metadata, including the self-hosted site's hostname in an Umami request header. The script respects browser blocking and its failure does not prevent the application from working.

The HTTP server also sends a host snapshot on startup and hourly while running: application version, Node major version, operating system, CPU architecture, coarse CPU core and RAM capacity ranges, host memory usage and load bands, process memory range, and process uptime range. The analytics server receives the host’s public IP address from these requests; no machine hostname or persistent installation ID is sent. OS-reported host memory and load may not reflect container limits. The visible-tab event can help estimate online browser sessions; it is not a count of people or all connected devices, and server events may also affect Umami’s active visitor count.

Only browser visits to the served landing page and web app are measured. CLI, API-only and native-app usage are not measured. Operators are responsible for any notice or consent requirements that apply to their deployment and users.
